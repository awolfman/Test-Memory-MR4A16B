# 🧠 MRAM Hardware Diagnostic & Stress-Test Tool

Шелл-скрипт (`/bin/sh`) для низкоуровневого стресс-тестирования, верификации и глубокого побитового анализа целостности данных энергонезависимой памяти **MRAM (емкостью 32 МБ)** в системах Embedded Linux.

Утилита разработана для автоматического поиска аппаратных дефектов: от локализации конкретной неисправной микросхемы из 16 распаянных на плате чипов до выявления физического «залипания» отдельных линий общей 32-битной шины данных.

---

## ✨ Ключевые возможности

* **Изоляция окружения (Safe Runlevel):** автоматически переводит встроенную систему в режим тестирования (`init 4`), останавливает конфликтующий сервис мониторинга `mkred` и корректно размонтирует точку `/mnt/mram`.
* **Стресс-тест записью (32 МБ):** генерирует случайный массив данных через `/dev/urandom`, напрямую заливает его в блочное устройство `/dev/mram0` блоками по 4 КБ и вычитывает обратно для сверки MD5-сумм.
* **Локализация дефектного чипа (Топологический анализ):** в случае расхождения данных делит адресное пространство на 8 логических блоков по 4 МБ и вычисляет, в какой именно из **16 микросхем (U1–U16)** произошел сбой.
* **Краш-анализ линий данных (XOR-анализ шины):** берет первый сбойный байт, переводит его в десятичный формат и с помощью побитовой операции `XOR` вычисляет, на какой именно линии 32-битной шины данных (**D0–D31**) произошло физическое залипание в «0» или «1».
* **Гарантированный откат (Graceful Cleanup):** при любом исходе (успех/ошибка/прерывание) скрипт подчищает за собой временные файлы в `/tmp`, форматирует MRAM утилитой `populate-mram.sh` и возвращает систему на исходный уровень инициализации (`init`).

---

## 🏗 Архитектура памяти и карта деградации

Скрипт опирается на следующую аппаратную топологию распределения памяти:
* **Шина данных:** 32-битная, разделенная на два 16-битных ранга (Стороны).
* **Размер блока:** 8 пар чипов. Каждая пара контролирует окно в 4 МБ адресного пространства.

| Адресное окно (МБ) | Сторона А (биты 0:15) | Сторона B (биты 16:31) |
|:---:|:---:|:---:|
| **0 – 4** | Чип `U1` | Чип `U9` |
| **4 – 8** | Чип `U2` | Чип `U10` |
| **8 – 12** | Чип `U3` | Чип `U11` |
| **12 – 16** | Чип `U4` | Чип `U12` |
| **16 – 20** | Чип `U5` | Чип `U13` |
| **20 – 24** | Чип `U6` | Чип `U14` |
| **24 – 28** | Чип `U7` | Чип `U15` |
| **28 – 32** | Чип `U8` | Чип `U16` |

## 📋 Системные требования

Скрипт оптимизирован для работы в легковесных окружениях (BusyBox) и требует минимальный набор утилит:
* Утилиты `dd`, `md5sum`, `cmp`, `awk`, `grep`, `sort`, `tr`.
* Наличие менеджера процессов `runit` или аналогичного (команда `sv`).
* Скрипт инициализации `/etc/init.d/populate-mram.sh` для восстановления структуры диска.

---

## 🚀 Запуск скрипта

Скрипт не требует передачи аргументов, но должен запускаться с правами суперпользователя (`root`), так как взаимодействует с уровнями выполнения системы и символьными/блочными устройствами:

```bash
sudo ./mram_test.sh
```

## 📊 Пример вывода при обнаружении дефекта

Если одна из микросхем повреждена или отошла пайка, скрипт выведет детальный отчет для сервисного инженера:

```text
================================================
 Проверка контрольных сумм MD5...
================================================
test failed (Обнаружено расхождение данных!)
================================================
Запуск глубокого анализа повреждения данных...
 -> АППАРАТНЫЙ ДЕФЕКТ: Сбой на Стороне А (чипы U1-U8, биты 0:15)
 -> СТАТУС СТОРОНЫ B: Успешно (Чипы U9-U16 исправны или данные не повреждены)
 -> РЕКОМЕНДАЦИЯ К ЗАМЕНЕ: Неисправны микросхемы [ U3 ]
 -> Анализ характера повреждений (по первой ошибке):
    Адрес: 0x008010A4 (Смещение: 8392869 байт, Чип U3)
    Ожидалось в байте: 184, Считано из MRAM: 152
    Локализованные сбойные биты на общей 32-битной шине (0:31):
    [*] Линия данных D5 ЗАЛИПЛА В 0 (Данные потеряны)
```

## 📂 Временные файлы

В процессе работы утилита создает и автоматически удаляет следующие файлы в директории `/tmp`:
* `/tmp/tomram` — эталонный массив случайных данных.
* `/tmp/frommram` — дамп, прочитанный обратно из микросхем.
* `/tmp/diff.log` — лог первичного несовпадения байт.
* `/tmp/chunk_to` / `/tmp/chunk_from` — исследуемые 4-мегабайтные срезы.
